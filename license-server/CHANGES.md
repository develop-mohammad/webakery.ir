# License Server — تغییرات جدید

## تغییر یوزرنیم و پسورد مدیر (بدون دست زدن به config)

در پنل ادمین → تب **«👤 تنظیمات حساب»**:

1. با یوزر/پسورد فعلی وارد شوید
2. رمز فعلی را وارد کنید
3. یوزرنیم جدید و/یا پسورد جدید را بگذارید و ذخیره کنید

پیش‌فرض داخل فایل نمونه:  
`ADMIN_USER = admin`  
`ADMIN_PASS = change-this-password`

اگر رمز فعلی را یادتان نیست، ریست اضطراری:

`/license-server/tools/reset-admin.php?key=RESET_NOW_2026`

بعد از ریست، همان فایل `reset-admin.php` را از سرور حذف کنید.

اعتبارنامه‌ها در `data/admin-auth.json` ذخیره می‌شوند (رمز با hash).  
**همه اطلاعات قبلی `config.php`** (دیتابیس، قیمت‌ها، گوگل، آپدیت‌ها و …) حفظ می‌شود.

## ۱. ایجاد لایسنس دستی برای دامنه + ایمیل

در پنل ادمین (`/license-server/admin/`)، فرم «ایجاد لایسنس دستی» حالا یک فیلد جدید **دامنه** هم دارد.

- قبلاً فقط می‌شد با ایمیل + پلاگین لایسنس ساخت و بعد از فعال‌سازی پلاگین روی سایت، دامنه ثبت می‌شد.
- حالا اگر فیلد «دامنه» را پر کنید، لایسنس همان لحظه روی آن دامنه هم فعال می‌شود و نیازی به فعال‌سازی دستی نیست.
- اگر فیلد دامنه خالی باشد، رفتار قبلی حفظ می‌شود.

### API
به `action=create` هم پارامتر `domain` اضافه شده:
```bash
curl -X POST https://webakery.ir/license-server/api/?action=create \
  -H "X-WBLM-Secret: YOUR_SECRET" \
  -d "email=user@example.com" \
  -d "product=wccp" \
  -d "domain=example.com"
```

## ۲. سیستم کد تخفیف

### ساختار کد تخفیف
هر کد تخفیف می‌تواند این ویژگی‌ها را داشته باشد:

| فیلد | توضیح |
|------|--------|
| `code` | کد قابل نمایش (با حروف بزرگ) — مثلاً `SUMMER20` |
| `type` | `percent` (درصدی) یا `fixed` (مبلغ ثابت به ریال) |
| `value` | درصد (۱-۱۰۰) یا مبلغ ثابت به ریال |
| `product` | `all` یا slug محصول خاص |
| `max_uses` | حداکثر استفاده (۰ = نامحدود) |
| `min_amount` | حداقل مبلغ سفارش به ریال (۰ = بدون شرط) |
| `expires_at` | تاریخ انقضا به میلادی (YYYY-MM-DD) — خالی = بدون انقضا |
| `status` | `active` یا `disabled` |
| `note` | یادداشت داخلی |

### در پنل ادمین
- یک تب جدید به نام **«🎟️ کد تخفیف»** اضافه شده.
- فرم ساخت کد تخفیف شامل پیش‌نمایش زنده (نمونه مبلغ نهایی برای محصول BAGET) است.
- کد پیشنهادی تصادفی هم زیر فیلد کد پیشنهاد می‌شود.
- در لیست کدها می‌توانید: ویرایش، فعال/غیرفعال، حذف کنید.
- شمارنده استفاده و وضعیت (فعال / منقضی / تکمیل شده) نمایش داده می‌شود.

### در صفحه پرداخت
- مشتری در صفحه `/license-server/pay/?plugin=...` یک فیلد «کد تخفیف» می‌بیند.
- دکمه «بررسی» کد را به صورت AJAX به `pay/check-coupon.php` می‌فرستد و مبلغ نهایی را پیش‌نمایش می‌دهد.
- بعد از پرداخت موفق، شمارنده استفاده کد یکی اضافه می‌شود.
- اطلاعات کد استفاده‌شده در جدول خریدها (`payments`) ذخیره می‌شود: `coupon_code`, `coupon_discount`, `base_amount`.

### API اعتبارسنجی کد تخفیف
بدون نیاز به کلید امنیتی، قابل استفاده برای فرم‌های پرداخت اختصاصی:

```bash
curl -X POST "https://webakery.ir/license-server/api/?action=coupon_validate" \
  -d "code=SUMMER20" \
  -d "product=wccp" \
  -d "amount=1990000"
```

پاسخ:
```json
{
  "success": true,
  "message": "کد تخفیف اعمال شد.",
  "discount": 398000,
  "final": 1592000,
  "coupon": { "code": "SUMMER20", "type": "percent", "value": 20, ... }
}
```

### لیست کدها از طریق API
فقط برای ادمین (نیاز به `X-WBLM-Secret`):
```bash
curl "https://webakery.ir/license-server/api/?action=coupon_list" \
  -H "X-WBLM-Secret: YOUR_SECRET"
```

## ۳. نمایش لایسنس دستی در پورتال مشتری

**مشکل قبلی:** وقتی ادمین لایسنس را دستی (با فقط ایمیل، بدون دامنه) می‌ساخت، کاربر نمی‌توانست از طریق فرم ورود دستی وارد پورتال شود، چون فرم ورود هم ایمیل و هم دامنه را الزامی می‌کرد.

**راه‌حل:** فیلد دامنه در فرم ورود پورتال **اختیاری** شد.

### نحوه ورود کاربر به پورتال (سه روش)

| روش | توضیح |
|------|-------|
| **Google OAuth** | با همون ایمیلی که لایسنس باهاش صادر شده، وارد میشه — ساده‌ترین راه |
| **ایمیل + دامنه** | اگر دامنه را هم وارد کند، ترکیب ایمیل+دامنه بررسی می‌شود (رفتار قبلی) |
| **فقط ایمیل** | اگر دامنه را خالی بگذارد، فقط بررسی می‌شود که لایسنسی برای آن ایمیل وجود داشته باشد → ورود موفق |

### تشخیص لایسنس دستی
- لایسنس‌هایی که در پرداخت‌های موفق ثبت نشده‌اند، به عنوان **«دستی»** شناخته می‌شوند.
- در پورتال مشتری: یک badge زرد «✋ دستی» کنار لایسنس نمایش داده می‌شود.
- در پنل ادمین: ستون جدید «منبع» با badge «✋ دستی» یا «💳 خرید».

### سناریوی کامل
1. ادمین در `/admin/` یک لایسنس دستی با ایمیل `user@example.com` (با یا بدون دامنه) می‌سازد.
2. کاربر به `/portal/` یا `/` می‌رود.
3. با Google OAuth (با همان ایمیل) وارد می‌شود → یا فقط ایمیل را در فرم دستی وارد می‌کند.
4. لایسنس در داشبورد نمایش داده می‌شود با badge «✋ دستی».
5. کاربر کلید را کپی می‌کند و در پلاگین وردپرس خود وارد می‌کند.

## فایل‌های تغییر یافته

| فایل | نوع تغییر |
|------|-----------|
| `includes/Database.php` | افزودن کل `coupons` و متدهای کوپن + متدهای `license_exists_for_email` و `payment_paid_exists_for_email` |
| `includes/LicenseManager.php` | پارامتر `domain` به `create()` + کلاس جدید `CouponManager` |
| `admin/index.php` | فیلد دامنه + تب «کد تخفیف» + ستون «منبع» (دستی/خرید) |
| `pay/index.php` | فیلد کد تخفیف + اعمال تخفیف در پرداخت + ذخیره در payment |
| `pay/check-coupon.php` | (جدید) endpoint AJAX برای پیش‌نمایش تخفیف |
| `api/index.php` | `domain` در `create` + `coupon_validate` + `coupon_list` |
| `index.php` | فیلد دامنه اختیاری در ورود + badge «دستی» |
| `portal/index.php` | فیلد دامنه اختیاری در ورود + badge «دستی» |
| `data/licenses.json` | کلید `coupons` (آرایه خالی) به فایل موجود اضافه شد |

## نکات مهم

- فایل `data/licenses.json` به صورت خودکار با کلید `coupons` سازگار می‌شود (در `Database::load()` چک می‌شود). فایل‌های قدیمی بدون این کلید هم کار می‌کنند.
- کدهای تخفیف case-insensitive هستند (در `_find` uppercase می‌شوند).
- تخفیف از نوع درصدی روی قیمت پایه (بعد از تخفیف زمان‌دار `LS_PROMOS` اگر فعال باشد) محاسبه می‌شود.
- اگر تخفیف بیشتر از مبلغ اصلی شود، به مبلغ اصلی محدود می‌شود (قابل پرداخت منفی نمی‌شود).
- ورود به پورتال با فقط ایمیل ممکن است (دامنه اختیاری است) — اگر لایسنسی برای آن ایمیل وجود داشته باشد.
- لایسنس «دستی» = لایسنس‌ای که کلیدش در پرداخت‌های موفق ثبت نشده (توسط ادمین ساخته شده).
